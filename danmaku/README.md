# 斗法托管（图像识别版）

修仙试炼 ·「弹幕斗法」的**真打**托管：不伪造请求、不注入页面脚本、不改游戏状态，
就是盯着屏幕看，判断弹幕往哪飞，然后把鼠标指针挪到安全的位置。

* 前台：Chrome 插件（状态、开关、日志）
* 后台：本地 Python 进程（抓屏 → 识别 → 决策 → 动鼠标）

和鱼鱼谷主程序（`gui/` 的 Node 托管）**完全独立**，不共用端口、不共用配置。

---

## 为什么是这条路

弹幕斗法是纯前端判定（`new4/xs/danmaku.js`），服务端只认「起止时间 ≥ 关卡下限」
和「符卡收取数上限」。想自动打，最稳的路子就是**真的去打**：
像素里看得见的，机器人就能躲；网页自己算的胜负，网页自己提交。

这也避开了禁区——不碰 `xsFight / xsWin / xsLose / xsRoot / xsStory`
这五个禁止提交的动作。

## 怎么跑

1. **装插件**：Chrome → `chrome://extensions` → 打开「开发者模式」→
   「加载已解压的扩展程序」→ 选 `danmaku/` 目录。

2. **装一次 Native 宿主**（只装一次）：在 `danmaku/` 目录里**双击
   `一键安装.bat`**。脚本会从浏览器的扩展列表里认出本目录对应的扩展 ID
   （由加载路径反查，认不出时才需要加 `--ext-id=<ID>`），生成
   `native/com.baicai492.danmaku.json`，把清单路径写进
   `HKCU\Software\Google\Chrome\NativeMessagingHosts`（顺带注册 Edge），
   最后做一次自检。

   装完如果是第一次加 `nativeMessaging` 权限，Chrome 会要求重新确认，
   在 `chrome://extensions` 里点一下扩展上的刷新按钮即可。

3. 打开斗法页面，进入战斗，点插件图标 →「开始托管」。
   **Python 服务会自己起来**，不用先双击 `启动.bat`。

> 想手动起服务也行：双击 `danmaku\启动.bat`（或 `python start.py`）。
> 服务已经在跑时，插件会直接用它，不会重复起进程。

托管期间**必须让斗法那个标签页保持在前台**：游戏自己监听了 `visibilitychange`，
标签页一藏起来就自动暂停（`danmaku.js:149`），机器人再厉害也打不了暂停中的游戏。
浏览器窗口不能被别的窗口盖住，否则抓到的不是游戏画面。

## 工作原理

```
mss 抓屏 ──► 找 #b77732 棕框（场地定位）──► 裁剪 + 2 倍放大
                                              │
        ┌─────────────────────────────────────┴──────────────┐
        │ HSV 双阈值 → 连通域 → 距离变换找弹芯峰值（每颗弹一个峰）│
        │ 细长条 → 激光；无芯大块 → 敌机（接触判定 size*0.25）  │
        │ (8,6)-(376,12) 血条 → Boss 血量 / 是否 Boss 战        │
        └─────────────────────────────────────┬──────────────┘
                                              │
              最近邻贪心跟踪（穿自机挖空区的弹靠速度外推）│
                                              │
        枚举 24 方向 × 3 半径的候选落点，沿飞行路径模拟 0.45 秒 │
        取「全程离所有威胁最近距离」最大的那个 ──────────────► SetCursorPos
```

* **自机怎么控制**：游戏里自机是「朝鼠标指针匀速飞」（300 逻辑像素/秒），
  所以唯一控制量就是指针位置。
* **开火**：这个游戏是自动射击，不需要点鼠标。右键是符卡（清屏保命），
  余量实在不够时才会放。
* **自机会被挖掉**：自机的鲸鱼雪碧图和敌弹阈值区间完全重叠，
  不挖掉机器人会躲自己；挖掉以后靠轨迹外推继续跟踪穿过去的子弹。
* **抓屏在后台线程**：mss 抓一次区域要 17 毫秒（整屏 33 毫秒），压在每帧上
  就把帧率锁在 8 fps 上下。现在后台线程连续抓、主循环只取最新一帧，
  抓屏和识别并行，帧率上限从「两者之和」变成「两者取大」。
* **Boss 在场时 HUD 会往下挪**（`danmaku.js:266` 的 `hy=boss?66:16`），
  识别时按有没有血条挖掉对应的文字带——不挖的话两行白字会被当成几十颗子弹，
  整局都在躲空气。
* **阈值是对着线上真实美术校准的**（2026-11-15，用 `offline/` 里的复刻版量的）：
  弹芯 V 中位 255、S 中位只有 79，旧参数（S≥135）只认出 24% 的弹。
  背景里那层漂浮的橙色萤火 V≈235，所以真正的分界线是**亮度**：
  弹芯阈值 V≥240 时召回 76%、误检比 V≥215 少 15 倍。
* **自机周围另有一遍放宽的补检**（`vision.detect_near`，半径 120 逻辑像素）：
  全局阈值为了压背景误检卡得严，近身这一圈放宽到 V≥230，
  近身召回 83%→92%，窗口内只多 0.2 颗误检/帧。决定生死的本来就只有近身这一圈。
* **自机自己的弹按方向剔除**：自机弹 380~820 像素/秒向上，敌弹最快 240。
  「向上快过 350」的一律不是威胁——以前 60~90 颗自机弹全被当成敌弹，
  走位被自己的弹幕逼得到处乱撞。
* **静止的背景亮点会被拉黑**：真弹最慢也有 60 像素/秒，背景视差只有 14~30。
  追踪 8 帧还没快过的轨迹判成背景（判据是「历史的快帧数」，
  剑符的悬停弹只是停一会儿，之前飞得很快，不会被误删）。

## 自动拉起是怎么做的

Chrome 只允许扩展通过 **Native Messaging** 启动本地进程，所以链路是：

```
popup 点「开始托管」
  → background.js 收 onMessage
  → chrome.runtime.sendNativeMessage('com.baicai492.danmaku', {cmd:'launch', port})
  → Chrome 执行 native/danmaku-host.bat → python/native_host.py
  → 宿主 detached 起 python/server.py（日志写 logs/danmaku-server.log）
  → 宿主探到端口通了才回话（最多等 15 秒）
  → popup 再 POST /api/start
```

几个容易踩的点：

* **停止托管会把服务一起关掉**：由插件拉起的服务带 `--managed` 标记
  （`/api/status` 里能查到），点「停止」时 popup 先 `POST /api/stop`
  停引擎、松鼠标，再 `POST /api/exit` 让整个进程退出，不会在后台留一个
  空转的 Python。手动双击 `启动.bat` 起的服务不在此列——那种 `managed`
  是 false，停止只停托管，进程留着给你自己用。
* **stdout 是协议通道**：宿主的 stdout 上只能是「4 字节小端长度 + JSON」，
  一个多余的 `print` 就会让 Chrome 判定消息损坏。所以宿主的日志全写文件。
* **服务已经在跑就直接复用**：宿主先探端口，通了就返回 `running`，不会再起一个抢端口。
* **僵死进程会被清掉**：有 PID 但端口不通时先 `taskkill`，避免旧进程占着不放。
* **popup 不能直接调 `sendNativeMessage`**：这是一次性连接，用户点完就关面板的话，
  Chrome 会连宿主进程一起收掉。所以中转放在 service worker 里。
* `shutdown` 先 POST `/api/stop` 和 `/api/exit`（先把鼠标松开、再关服务器），
  实在不退才 `taskkill`。

## 离线复刻版（`offline/`）

不用登录、不用真实屏幕，在本机跑**和线上逐字节一致**的斗法：
`danmaku.js` / `ui.js` / `xs.css` / 19 张美术资源都是从 52dmeme.com 原样下载的，
`verify.py` 会重新拉一遍线上文件和本地比对。

```
cd danmaku\offline
python verify.py                 :: 校验本地副本和线上逐字节一致
python run.py secret --seconds 60   :: 让引擎在复刻版上真打一局
python bench.py secret 70        :: 闭环评测：召回 / 误检 / 受击 / 帧率
python bench_oracle.py secret 60 :: 对照实验：把游戏真值弹位直接喂给走位器
```

* 画面用 headless Chrome + `Page.startScreencast` 推流（16ms/次，实测 22 fps），
  引擎一行不用改——`CastScreen` 冒充 `Screen`，`CastMouse` 派发 `pointermove`。
* 真值来自 `danmaku.js:277` 自带的 `window.__dm`（`?xsdebug` 时暴露），
  每帧可以拿弹位/自机/命数对账。
* `bench_oracle` 是关键的对照：真值喂给走位器 60 秒 0 受击，说明走位算法没问题，
  剩下的受击都是「看不见」造成的。

## 离线自测（模拟器）

复刻版之外，`python/sim.py` 里还有一个「照着线上截图近似画」的模拟器，
不依赖浏览器，专门用来做版本之间的相对退化检查（同口径跑，受击数对比）。

```
cd danmaku\python
D:\miniconda\envs\py311\python.exe selftest.py           :: 200 秒虚拟时间的一局
D:\miniconda\envs\py311\python.exe selftest.py --dump D  :: 存标注图，肉眼看识别对不对
```

最近一次结果（0.2.1，阈值改成对着真美术校准后的值）：

```
场地定位：20/20 成功，最大误差 3.0 屏幕像素
子弹检测：命中 90.0%（误检 1622，其中含自机子弹/道具/敌机）
Boss HUD 掩码：文字带内残留 0 颗（同一帧不挖文字带时 1 颗）
闭环：模拟 129 秒，胜，被击中 0 次，放符卡 1 张
```

复刻版上（`offline/bench.py secret 70`，同口径，抓屏链路和线上一样）：
近身 120 像素内召回 88~96%，误检 5~20 颗/帧，70 秒一局受击 0~1 次。
`bench_oracle`（真值直接喂走位器）同样 60 秒 0 受击，两条线对得上。

模拟器的弹幕比线上真实关卡密得多，闭环这一项主要用来看**版本之间的相对退化**。
`--seed N` 换背景随机种子。

## 设置项

| 项 | 默认 | 说明 |
|---|---|---|
| 演练模式 | 关 | 只识别不动鼠标。第一次用建议先开，确认「敌弹/敌机」数字和画面相符 |
| 自动放符卡 | 开 | 最优路线的余量也不到 3 像素时放符卡清屏 |
| 预判时长 | 0.45 秒 | 看多远。短一点更保守，长一点更早转向 |
| 反应 | 标准 | 放大安全余量（灵敏 = 更贴弹，稳 = 离弹更远） |
| 识别帧率 | 30 | 识别本身约 20 毫秒；抓屏在后台线程并行，实际帧率看面板 |

## 已知限制

* **暗场阶段**（魔修长老第 3、4 幕、雷属性切磋第 3 幕）：游戏只给自机和 Boss
  周围挖个洞，外面全黑。看得见的半径约 90 逻辑像素，等于把预判距离压到
  0.3~0.6 秒，这一段会比平时危险。
* **标签页必须在前台**：切走标签页游戏自己会暂停（不是本程序的问题）。
* **判定点**：游戏里真正的判定半径是 2.2 像素（`d < b.r + 2.2`），
  机器人按「保守膨胀」的半径算，比真人更怕死，偶尔会为了躲一颗远弹而
  跑到更差的位置。
* 一局打完**不会**自动点「再来一局」——那属于操作游戏界面，不在本程序范围。
* 游戏在副屏时用 `python start.py --monitor 0`（抓所有屏幕拼起来的那一块）。
